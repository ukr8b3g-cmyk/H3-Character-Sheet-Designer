# H3 Character Sheet Designer 初版実装仕様

更新日 2026年10月3日

本書は独立したComfyUIカスタムノードの実装契約を定める。選択したビューから英文プロンプトと出力寸法を決定し、既存のネイティブH3参照ノードへ渡す。本書は実装前に確定した契約を保持する。実装コードと自動試験を追加済み。現在の検証範囲と未検証事項は [VERIFICATION.md](VERIFICATION.md) を参照。実ComfyUIフロントエンドとGPU生成は未検証。

## 1 範囲とノード契約

| 項目 | 初版の契約 |
| --- | --- |
| 登録ID／表示名 | `H3CharacterSheetDesigner`／`H3 Character Sheet Designer` |
| 入力 | 必須 `state_json: STRING` 1個。完全な既定JSONを持ち、動的プロンプト展開を無効化 |
| 出力 | slot 0 `prompt: STRING`、slot 1 `width: INT`、slot 2 `height: INT` |
| 生成状態 | `state_json` という名前のwidget値。UIとAPIで同じJSON文字列を使用 |
| 依存 | ComfyUI、Python標準ライブラリ、ブラウザー標準HTML/SVG |

Designer自身はLLM・外部API・追加モデルを必要としない。Pythonを配置・寸法・promptの唯一の確定実装とし、JavaScriptは入力操作、構造検証、意味状態の保存、プレビュー表示を担当する。

接続は `Designer.prompt/width/height → MiniMaxH3ReferenceToVideo`。人物参照画像は別のLoadImageからネイティブノードの最初の画像参照へ渡す。`<Picture 1>` は下流で実際に列挙される最初の画像であり、Designerは下流接続や画像内容を検査しない。初版の説明例は参照画像1枚を前提とし、複数画像の役割割当は範囲外。

モデル読み込み、参照画像、latent、サンプリング、デコード、フレーム抽出、保存は既存ノードの役割。Ref2VAモデルを使う例を示す。Continuumの既存ノードや保存済みワークフローは変更しない。初版では画像解析、自動切り抜き、別生成の合成、10パネルUIを追加しない。

## 2 状態スキーマ

```json
{
  "schema_version": 1,
  "views": ["face_front", "body_front", "body_left", "body_back"],
  "size": {
    "mode": "auto",
    "body_height": 1120,
    "manual_width": 2240,
    "manual_height": 1280
  }
}
```

高解像度を優先し、Autoの既定基準高は1120。既定出力は2208×1280。保存されたManual寸法2240×1280はAuto出力ではない。低負荷候補672への変更は利用者が明示的に行う。

- JSONはUTF-8最大16 KiB。オブジェクトの重複キー、NaN／Infinity、未知キー、欠落キー、未知ID、空選択を拒否する
- 整数項目にbool・小数・数値文字列を受け付けない。`schema_version` も厳密な整数1のみ
- `views` は文字列配列とし、重複を除いて `face_front, body_front, body_left, body_back, hands, feet` の固定順へ正規化する
- `mode` は `auto` または `manual`。全サイズ項目は32以上の32倍数で、実行時の `nodes.MAX_RESOLUTION` 以下。Autoの計算結果も各軸の上限を検証する
- 未知バージョン・不正な保存JSONは原文を保持し、エラーを表示して実行を拒否する。既定値への黙示的置換や自動移行はしない
- 将来の移行はバージョン別に明示する。locale、プレビュー、SVG、生成prompt、導出寸法、開閉状態は生成JSONに含めない

GUIからの書き出しは上記のキー順、不要な空白なし、固定ビュー順とする。APIは同じ意味の別キー順・空白を受け付け、Pythonで正規化する。状態の意味が同じなら出力promptバイト列を同一にする。生成結果そのものの決定性はこの契約に含めない。

## 3 ビューとプリセット

| ID | 表示／意味 |
| --- | --- |
| `face_front` | 正面の顔から胸まで |
| `body_front` | 正面全身、頭頂から靴底まで |
| `body_left` | 人物の解剖学的左側をカメラが見る、厳密な左プロフィール全身 |
| `body_back` | 真後ろの全身 |
| `hands` | 左右の手の詳細。参照に手袋があれば保持 |
| `feet` | 左右の足・履物の詳細。靴やブーツの筒を保持 |

左右は人物基準。`body_left` の自然言語は「camera looking directly at the subject's anatomical left side」とし、「鼻がシート左」と併記しない。UIアイコンも同じカメラ基準に合わせる。鏡像や左右非対称衣装の正確な再現は保証しない。

| プリセット | ビュー |
| --- | --- |
| 基本4面 | 顔、全身正面、左側面、背面 |
| 6面・ディテール | 基本4面、手、足 |
| 三面図のみ | 全身正面、左側面、背面 |
| 1カット | 全身正面 |

プリセット操作はビューだけを変更し、Auto／Manualと保存サイズ値を維持する。名称は選択から導出し、その他は「カスタム」。最後の1ビューはUIで解除できず、説明を表示する。APIの空選択は入力エラー。顔のみ、左側面のみ、手のみ、足のみ、手＋足も正規の選択である。

## 4 配置と寸法

以下はDesigner独自のレイアウト規則であり、H3の公式推奨比率やハード座標制御ではない。Autoは「要求する全身パネルの高さ」を維持する。生成画像内の人体の実ピクセル高まで保証する意味ではない。

### Auto

`h=body_height`、外周余白 `m=h/14`、列間および補助枠間の隙間 `g=h/25`、全身列幅 `b=2h/5`、補助列幅 `a=h/2` とする。

補助ビューが1個以上あれば左端に幅a・高さhの補助列を1本作る。全身ビューは固定順に右へ、それぞれ幅b・高さhの列を作る。補助ビューがなければ補助列を作らない。非空選択なので列数nは必ず1以上。

補助列の内部は次のように割り当てる。

- 顔だけ：全高h
- 顔＋詳細：顔の高さ `31h/50`、下に隙間g、その下の詳細帯は高さ `h−31h/50−g`。手・足の両方がある場合は詳細帯を隙間gを挟んで左右に等分し、手を左、足を右にする。片方なら全幅
- 顔なしの手＋足：隙間gを挟んで縦に等分し、手を上、足を下にする
- 手または足だけ：全高h

列群の理想キャンバスは `W*=列幅合計+(n−1)g+2m`、`H*=h+2m`。W*とH*をそれぞれ次の32倍数へ切り上げる。増えた余白は左右・上下へ均等配分し、パネル内部を拡大しない。全身がある場合はパネル上下端と靴底基準線を共通にする。全身がない場合は `feet_y:null` とし、promptへ全身共通縮尺や靴底線の指示を追加しない。

計算は有理数で行う。最終的な正規化座標のみ小数6桁、round-half-upで丸める。矩形は `[left,top,width,height]`、原点は左上、範囲は0～1。丸めによる誤差は1e−6程度として試験し、負のゼロは0へ統一する。入力値を勝手に32へ丸める処理とは区別する。

| 選択 | h | Auto出力 | 画素数 |
| --- | ---: | ---: | ---: |
| 基本4面／6面・既定 | 1120 | 2208×1280 | 2,826,240 |
| 三面図のみ | 1120 | 1600×1280 | 2,048,000 |
| 全身1カット／左側面のみ | 1120 | 608×1280 | 778,240 |
| 補助列のみ | 1120 | 736×1280 | 942,080 |
| 基本4面／6面・低負荷候補 | 672 | 1344×768 | 1,032,192 |
| 三面図のみ | 672 | 960×768 | 737,280 |
| 全身1カット | 672 | 384×768 | 294,912 |

基本4面から6面にしても補助列の有無は変わらないので出力寸法は同じ。補助列が消える場合だけその列と列間隙間がなくなる。高さ候補は672／896／1120／1344／1792。32倍数の任意基準高も指定できる。

### Manual

幅・高さを利用者が指定し、ビュー／プリセット変更で値を変えない。理想キャンバスW*×H*をManualキャンバスへアスペクト比維持で一様に収める。倍率は `s=min(W/W*,H/H*)`、余りは外周へ均等配分する。Autoの32丸め後の余白をManualへ持ち込まない。Manualでは選択変更でパネルの見かけの大きさが変わり得る。

AutoからManualへ切り替える際は、現在の状態と一致するプレビュー応答のW・Hを両方コピーしてから、利用者の寸法編集を適用する。プレビューが最新でない間、この遷移操作だけを無効化して「寸法更新中」と表示する。古いプレビュー寸法を黙って採用しない。Manual中の寸法変更・ビュー変更は同期的に確定できる。「Autoに戻す」は保存済みManual値を保持する。

数値欄の未確定draftは生成状態と分離する。Enter／フォーカス離脱で検証し、有効値だけ同期確定。不正なdraftは理由を表示する。未確定の数値入力がある間は「未確定の値は保存・実行されません」とその欄に明示する。ビューのクリックはdraft扱いにせず即時確定する。

### 高解像度

画素数とMPを常時表示する。`P>1,032,192` の場合はExperimentalと表示する。これはDesignerの注意表示用閾値であり、ネイティブH3出力の強制上限ではない。閾値超過を理由に縮小・拒否しない。各軸のCore上限超過は構造エラーとして拒否する。利用可能VRAM、処理時間、モデルの品質は保証しない。5フレームでもAVモデルの通常生成経路を使うため、通常の静止画モデル相当の軽さを約束しない。[Core定義](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_extras/nodes_minimax_h3.py)

## 5 英文プロンプト

固定テンプレートで次の6節を順に出力する。

`subject_definitions → summary → retention_analysis → detailed_description → overall_soundscape → non_diegetic_music`

`<Subject 1>` を `<Picture 1>` の人物と定義する。summaryは `[reference generation]` で始める。retention_analysisには対象・保持役割を記述し、detailed_descriptionは1つの `[Shot 1]` に完成した静止シートを記述する。参照の不可視面は控えめな推測にとどまる旨を含める。音・音楽はなし。[公式Ref2VAの構成](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/references/ref-en.txt)

同一人物の選択された別ビューを同時表示し、顔・髪・体格・肌・絵柄・衣装・小物を保持するよう指示する。全身と詳細を区別し、参照にある手袋や履物を裸の手足へ置換しない。選択されていないビューや追加人物、文字、枠線、動作、カメラ移動、時間的切替を要求しない。詳細のみの選択に「全身を表示」といった矛盾する文を追加しない。

detailed_descriptionに `canvas:[W,H]`、パネルごとの `id/rect/view/content`、`feet_y` を含む配置JSONと、同じ配置の自然言語を併記する。これはモデルが読む意味指示であり、CoreにJSON解析器や座標拘束を追加するものではない。SVG、アイコン色、UI文字、HTMLは含めない。

生成promptは常に英文。固定順・固定改行LF・固定数値表記・末尾改行の有無をテンプレートで固定し、snapshot試験で管理する。UI言語、選択順、JSONキー順で出力を変えない。DesignerのSTRINGには動的プロンプト展開を設定しない。出力文字列を下流へ接続して、JSONの波括弧が展開されずそのまま届くことを統合試験する。

下流例は `length=5` フレーム、`ref_image_size=match`。これは短い静止シート生成の実験設定で、5秒ではない。Designerは下流設定を自動変更しない。画像として保存したい場合は下流でデコードしたフレームを選択・保存する。

## 6 UIと状態確定

初期サイズは利用者指定の870×930とし、既存の大きいノードは縮小しない。文字は基本18px、主要ラベル16px、補足14pxとし、暗背景でのコントラストを確保する。基準高は値の表示欄全体を押して選ぶ通常のドロップダウンとし、任意値は「手入力…」を選んで別の数値欄から指定する。18px幅の矢印だけを別selectにする方式は使わない。上に短い案内と選択数、6つのカードを横並び、その下にプリセット、Auto／Manual、基準高、幅×高さ、Autoへ戻す操作、下部に高さ230px以上を確保し余白に応じて伸びるプレビューを置く。狭い幅では操作行を折り返し、ラベルや入力を切らない。画像出力寸法に合わせてノードを巨大化しない。

カードとプレビューには輪郭、陰影、量感を持つ疑似3Dマネキンを表示する。2026年10月3日の利用者指定により、通常表示にはGPT Imageで生成した、髪や表情を持たず、履物の具体的な意匠を避けた中性的なローポリマネキンの同梱PNGを使う。SVGはPNGのアトラス表示枠と、画像読み込み失敗時の簡素なローカル代替図に限る。実行時の外部画像API呼び出しは行わない。選択境界とチェックは青緑、未選択は減彩。色だけに依存せず、選択状態を `aria-pressed` 等でも示す。キーボード操作と日英ラベル・短いtooltipを用意する。SVGのgradient等のIDはDOMインスタンスごとに一意にする。人物画像やUIマネキンを生成入力へ送らない。

### 同期確定と非同期プレビュー

1. ビュー／プリセット／有効数値の1操作ごとに、現在の意味状態から次状態を作る
2. JSの小さな構造検証と固定順シリアライズを行い、`state_json` widgetの値を同期的に確定する。Pythonの配置計算・prompt生成はJSへ移植しない
3. 確定をComfyUIの変更トランザクションとして記録する。1操作＝1Undo。再描画やlocale変更をUndo項目にしない
4. 同一ComfyUIサーバーの `POST /h3_character_sheet_designer/preview` に最新state_jsonを送り、Pythonの共通 `parse/normalize/layout/size/compile` 経路から配置と寸法を得る
5. 応答は表示専用。ノード世代番号、要求番号、送信したstate_jsonがすべて現状態と一致したときだけ表示する。応答から保存widgetを上書きしない

クリック直後にSave／API出力／Queueしても、そのクリック後の確定意味状態を使用する。プレビュー待ちを理由に以前の確定選択へ戻さない。プレビュー待ちは現在の選択を示し、寸法・レイアウトには「更新中」を表示する。以前のプレビューを残す場合は古い表示であることを明示する。

プレビュー通信失敗でも状態はロールバックしない。再試行を表示し、Queue時にはPythonが現在のstate_jsonを直接検証・コンパイルする。Python検証エラーは表示し、実行を失敗させる。古い成功結果を代わりに実行しない。未完了要求はUndo／Redo／読み込み／削除で無効化する。連続クリックは直前の最新意味状態から計算する。永続状態が同一になって戻るケースでも世代番号で旧応答を破棄する。

previewエンドポイントは認証・アクセス制御をComfyUIに従わせ、外部ネットワーク、ファイル書き込み、モデル実行を行わない。HTTP本文も小さな上限を設け、未知スキーマ・過大JSONを早期拒否する。これはGUI表示の便宜であり、API／headless実行に呼び出し必須の経路ではない。

## 7 保存とフロントエンド互換性

`state_json` を唯一の生成入力とする。通常STRING widgetとカスタムDOMwidgetを同時に生成状態の所有者にしない。名前で元widgetを特定し、同じシリアライズ位置を維持する。DOM表示用に別widgetを追加する実装を選ぶ場合、それは非保存かつAPI非入力であることを実機で確認する。

`widgets_values[0]` を外部契約にしない。ComfyUIのバージョンによって位置配列と名前付き値が存在するため、標準のwidget保存／復元経路を使い、名前 `state_json`、APIの `inputs.state_json`、保存再読込の値一致を契約とする。独自の二重保存やasync serializeを追加しない。[現行の保存実装](https://github.com/Comfy-Org/ComfyUI_frontend/blob/main/src/lib/litegraph/src/LGraphNode.ts)

DOMwidgetは `getValue/setValue` で文字列を取得・復元する。setterは復元とUndoにも使われるため、既定値で上書きせず、現在の値から表示を作り直す。新規、復元、複製それぞれで独立したDOM・状態・要求管理を作る。[DOMwidget実装](https://github.com/Comfy-Org/ComfyUI_frontend/blob/main/src/scripts/domWidget.ts)

拡張フックを優先し、グローバルprototypeを変更しない。必要なinstanceフックの連鎖では既存処理と戻り値を維持する。保存済み値を読むのはconfigure後とし、読み込み完了処理には `afterConfigureGraph` 等を用いる。削除時にイベント・リクエスト・DOM参照を解放する。[フック](https://docs.comfy.org/custom-nodes/js/javascript_hooks)

Undoは対象バージョンのgraph／canvas変更トランザクションに接続し、再描画だけで済ませない。内部storeの直接importを必須にしない。現在の変更追跡コードはbefore／after-changeを処理するが、これだけで全バージョン対応済みとはしない。[変更追跡実装](https://github.com/Comfy-Org/ComfyUI_frontend/blob/main/src/scripts/changeTracker.ts)

DOM非対応では1個の通常STRING入力へ戻し、GUIデザイナーを利用できないことを明示する。APIコンパイルは継続可能。対応確認前のNodes 2.0や古いfrontendを対応済みと表記しない。最低対応版は実装試験の結果で確定する。[Nodes 2.0の現状](https://docs.comfy.org/interface/nodes-2)

## 8 日本語と英語

`app.extensionManager.setting.get("Comfy.Locale")` を優先し、取得APIがない場合のみ `app.ui.settings.getSettingValue("Comfy.Locale")` を利用する。値を小文字化して基底言語タグがjaなら日本語、それ以外・取得不能は英語。ブラウザー言語では上書きしない。[設定API](https://docs.comfy.org/custom-nodes/js/javascript_settings)

現行の互換イベント `app.ui.settings` の `Comfy.Locale.change` をfeature detection付きで購読する。自分の設定ではない `Comfy.Locale` を再登録したり、既存onChangeを置換したりしない。イベントのない版は再読込で反映する。削除時に購読解除する。[イベント定義](https://github.com/Comfy-Org/ComfyUI_frontend/blob/main/src/scripts/ui/settings.ts)、[発火経路](https://github.com/Comfy-Org/ComfyUI_frontend/blob/main/src/platform/settings/settingStore.ts)

locale変更は表示テキストだけを変え、state_json、prompt、寸法、Undo履歴を変えない。

## 9 実装順と受け入れ試験

### P0 保存と即時実行

まず最小ノードで1STRING・3出力を定義し、名前による保存、DOM表示、通常STRING fallbackを確認する。Save→再読込、複製、Undo／Redo、API出力、複数インスタンスを試験する。クリック直後のSave／Queue、連続クリック、Undo中の古い応答、A→B→Aの遅延応答、削除後の応答を必須ケースとする。UIとAPIのstate_json一致を確認する。

### P1 Pythonコンパイラ

全63非空選択について矩形の正のサイズ、キャンバス内、非重複、固定順、全身があるときの共通基準線、全身がないときのnull基準線を確認する。Auto表の算例、32倍数、上限境界、Manual寸法維持、Auto→Manualの最新寸法コピーを確認する。重複／未知キー、欠落、NaN、bool、小数、過大JSON、未知バージョン、空選択のエラーを試験する。

全プリセットと単独ビューのprompt snapshotを保持する。GUI言語、入力順、JSONキー順、空白が違っても同じ意味状態から同じ結果になることを確認する。APIはpreviewエンドポイントを呼ばず実行できることを確認する。

### P2 UI

## 10 仕様初版公開時点の検証範囲（履歴）

公式Core・frontend・H3 prompt資料を参照し、ノード契約、設定イベント、保存経路、配置式を設計レビューした。独立した有理数計算で上表の寸法・画素数を照合し、h=1120の全63非空選択についてパネル数、正のサイズ、範囲内、非重複を確認した。これは製品コンパイラやGUIの試験ではない。仕様初版公開時点ではP0～P3は未実施であり、実行可能コード、GPU品質、全バージョン互換性を主張しない。

正確な人数、解剖学的側面、不可視面、衣装、配置はpromptだけでは保証できない。高解像度は利用者が選択できる実験設定として公開し、生成画像による評価は実装後に行う。
